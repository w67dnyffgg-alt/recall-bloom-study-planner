# 既存データを守る、Rememoの段階的な改善

## 現在の状態
- 学習記録と復習履歴は、Lovable Cloudの2種類のデータとして保存されています。復習履歴は学習記録のIDに紐づき、ログインした本人だけが読み書きできます。
- 科目名と教材名は現在、各学習記録に文字として保存されています。独立した科目・教材の管理はまだありません。
- ホーム、学習記録、カレンダーは同じデータ取得処理を利用しています。復習間隔の計算は独立しており、変更せず維持できます。
- **この計画の承認は、移行完了の確認とは別です。既存データとログインは削除しません。**

## 第1段階：クラウドデータの保全
1. 現在のログインを維持し、設定画面に既存データのJSONエクスポートを追加します。
2. 本人の学習記録と復習履歴をすべて取得し、取得漏れを防ぎます。取得に失敗した場合は、不完全なバックアップを作成しません。
3. 元のID、学習日時、復習日時、段階、評価、メモをそのまま保存します。作成日時と形式のバージョンを含め、日時付きのファイル名にします。
4. 書き出したファイルを検証し、件数と紐づけを表示します。クラウドへの削除・更新は行いません。

## 第2段階：端末内保存と復元を追加
- IndexedDBに科目、教材、学習記録、復習履歴、設定を保存します。保存失敗時には明確に知らせ、成功したように表示しません。
- JSONファイルを選ぶと、作成日時、学習記録数、科目数、復習履歴数を表示します。形式、IDの重複、紐づけ、日時、復習段階を検証し、不正なファイルは保存前に拒否します。
- 「置き換える」と「統合する」を用意します。置き換え前には確認を必須にし、現在のデータを退避します。
- 統合では同じIDの同じ内容を重複登録しません。内容が異なる場合は、現在の内容と取り込む内容を比較して選択できるようにします。すべての選択と整合性確認が終わるまで変更しません。
- 別端末で同じ名称でも異なるIDの科目・教材がある場合、勝手に同一扱いしません。安全に紐づけられない組み合わせは取り込みを中止し、理由を表示します。

## 第3段階：既存データを端末へコピーして確認
1. ログインした状態で、第1段階のバックアップを作成します。
2. 既存の科目名から科目を、科目と教材名の組み合わせから教材を作成し、安定したIDで紐づけます。教材が空欄の記録は教材未指定として保持します。名称を勝手に修正・統合しません。
3. 学習記録・復習履歴のIDと、すべての復習日時・段階をそのまま端末へコピーします。過去や未来の予定を再計算しません。
4. クラウドと端末の件数、各記録の内容、履歴の紐づけ、復習予定を照合して結果を表示します。差異があれば切り替えを止めます。
5. 端末内データをホーム・学習記録・カレンダーで確認できるようにします。移行確認中は保存先を明示し、クラウドと端末を同時更新せず、元のクラウド表示へ戻れる状態を残します。

**ここで、実際の記録と復習予定が正しいことをユーザーに確認していただきます。確認を待つ間、ログイン機能とクラウドデータを残します。**

## 第4段階：科目・教材管理と入力改善
- 設定に「科目・教材管理」を追加し、追加・名称編集・削除を用意します。教材は科目に紐づけます。
- 名称変更後もIDで過去の記録との関係を維持します。記録のある科目・教材は削除不可にし、教材の残る科目の削除も防ぎます。
- 学習記録は「科目 → 教材 → 記録」の階層で絞り込み、学習履歴・復習予定・実施履歴を確認できるようにします。ホームは全科目をまとめます。
- 学習入力の科目・教材をプルダウンにし、選択科目の教材だけを表示します。前回の選択を端末に記憶し、選択した項目がなくなった場合は安全な初期値に戻します。
- 入力画面から科目・教材を追加できます。学習日時は現在日時、単元・ページは自由入力、メモは任意とします。
- 現在のライトグレー・淡いピンク・透明感のあるデザインを維持し、iPhoneで操作しやすい配置にします。

## 第5段階：バックアップと手動同期
- 設定の「データ管理」から、全データと設定をJSONでダウンロードします。Safariの通常のダウンロード・ファイル選択を使い、iCloud Driveへ保存・そこから読み込みできます。
- iCloudへの直接保存や自動同期は行いません。端末間の移動はバックアップを作成し、別端末で復元する方式です。
- 最終バックアップ日時を表示し、7日以上経過した場合はアプリを開いた際にお知らせします。未作成の場合も表示します。
- バックアップの生成とダウンロード開始が成功した場合だけ日時を更新します。ブラウザからiCloudへの実際の保存完了は確認できないため、その点を明示します。
- ブラウザ内データは通常の再読み込み・終了後も保持されますが、サイトデータ削除やブラウザの消去処理で失われる可能性があります。端末内だけでは完全な保全にならないため、バックアップを併用します。

## 第6段階：ユーザー確認後にログイン不要へ切り替え
- 移行完了の確認後、通常利用からログインを外し、端末内データで直接ホームを開きます。
- 学習記録の保存・取得や認証のためのクラウド通信を通常利用から外します。クラウド自体と元データは残します。
- 各端末のデータは独立します。保存領域はサイトのURLごとに異なるため、プレビューではなく実際に利用する公開URLでもバックアップから取り込み、確認します。
- 公開は勝手に行いません。公開版への反映が必要な段階でお知らせします。

## 技術・検証方針
- データアクセスを既存のフックに集約したまま、クラウドとIndexedDBを明確に切り替える保存層を追加します。移行中のローカルデータはアカウントごとに分離し、別アカウントに表示しません。
- IndexedDBでは復習履歴追加と次回予定更新を1つのトランザクションで処理し、片方だけ保存されるのを防ぎます。復元も検証後にまとめて反映します。
- 復習ルールは `src/lib/srs.ts` を引き続き使用し、間隔・評価の意味を変更しません。通知用の差し込み口も維持します。
- テストを追加：予定日時の完全保持、IDと関係の維持、使用中項目の削除防止、科目別教材選択、重複しない統合、競合時の未承認上書き防止、不正ファイルの拒否、7日のお知らせ条件、失敗時にバックアップ日時を更新しないこと。
- 実画面で、本人のデータを書き出し → 端末へ取り込み → 照合 → 再読み込み後の保持 → 学習登録と復習 → 別の端末相当の保存領域への復元を検証します。iPhone・iPad・Mac相当の幅も確認します。

## 今回の進め方
まず第1〜第5段階を段階的に実装し、移行の照合結果を確認できるところまで進めます。**第6段階のログイン廃止は、ユーザーによる移行完了の確認後に実施します。**
