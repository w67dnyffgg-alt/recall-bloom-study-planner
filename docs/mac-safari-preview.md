# MacのSafariで試す手順（無料）

今回の改修は `codex/local-preview-20261101` ブランチで試します。画面上のアプリ名は **Rememo** です。GitHubへコードを保存すること、Codexの環境を公開すること、Lovableの公開サイトを更新することは別の操作です。この手順ではLovableを公開・更新せず、クラウドの学習データも変更しません。

## 1. Node.jsを一度だけインストールする

1. Safariで https://nodejs.org/ を開きます。
2. **Node.js 24 LTS** のmacOS用インストーラー（`.pkg`）をダウンロードします。24系はCodexで動作を確認したバージョンです。
3. ダウンロードしたファイルを開き、画面の案内に従ってインストールします。支払い・アカウント登録は不要です。
4. Macの「ターミナル」を新しく開き、次を実行します。

```sh
node --version
npm --version
```

`v24…` とnpmのバージョンが表示されれば準備完了です。`command not found` と表示された場合はターミナルを閉じて開き直します。

## 2. 改修済みのコードをダウンロードする

1. Safariで次のページを開きます。非公開リポジトリの場合は自分のGitHubアカウントでログインしてください。

   https://github.com/w67dnyffgg-alt/recall-bloom-study-planner/tree/codex/local-preview-20261101

2. 表示されているブランチが **codex/local-preview-20261101** であることを確認します。`main` は選びません。
3. 緑色の **Code → Download ZIP** を選びます。
4. ZIPが自動的に展開されなければ、ダブルクリックして展開します。
5. 展開されたフォルダを、例えば「書類」フォルダへ移します。アプリを使う間は同じフォルダを残しておきます。

GitHubのマージ、Pull requestの作成、LovableのPublish操作は不要です。既存のサイトにはアクセスせず、このコピーをMac上で起動します。

## 3. ターミナルでそのフォルダを開く

1. 「ターミナル」で `cd ` と入力します。`cd` の後ろには半角スペースを1つ入れます。まだEnterは押しません。
2. Finderから、展開したアプリのフォルダをターミナルへドラッグします。フォルダの場所が自動入力されます。
3. Enterを押します。
4. 次を実行します。

```sh
ls package.json
```

`package.json` と表示されれば正しい場所です。見つからない場合は、ZIPそのものや親フォルダではなく、`package.json` が入っているフォルダをドラッグし直してください。

## 4. 必要な部品を入れる（初回のみ）

次の1行をコピーし、ターミナルへ貼り付けてEnterを押します。

```sh
npm exec --yes --package=bun@1.3.3 -- bun install --frozen-lockfile
```

無料のBunをnpmのキャッシュへ取得し、ロックファイルに記録された依存パッケージをインストールします。グローバルインストールや`sudo`は不要です。初回はインターネット接続が必要で、数分かかることがあります。

エラーが表示された場合は、それ以降のコマンドを実行せず、そのエラーをチャットへ伝えてください。APIキーやパスワードを入力したり、`.env` の内容を送ったりする必要はありません。

## 5. アプリを起動する（利用するたびに実行）

同じターミナルで次を実行します。

```sh
npm exec --yes --package=bun@1.3.3 -- bun run dev --host 127.0.0.1 --port 5173 --strictPort
```

`ready` と表示されたら、そのターミナルを開いたままにします。Safariのアドレス欄に次を入力します。

**http://127.0.0.1:5173/**

このアドレスは、上のコマンドを実行している **自分のMac** のアプリです。Codexのサーバーへ接続するアドレスではありません。Webに一般公開する操作も行いません。

最初の画面では **「ログインせず端末内で使う」** を押してください。「既存クラウドデータを利用・移行する」は今回の動作確認では選びません。

この操作だけでIndexedDBの利用を開始できます。新しいAPIキーやSupabaseの設定は不要です。

## 6. 最初はテスト用の記録で操作する

1. 「学習を記録」を押します。
2. 「科目を追加」で、例えば「テスト科目」を登録します。
3. 「教材を追加」で「テスト教材」を登録します。
4. 単元名に「テスト単元」と入力して記録します。
5. ホームとカレンダーで復習予定を確認します。
6. Safariを再読み込みし、記録が残ることを確認します。
7. 「設定 → バックアップを作成」でJSONをダウンロードします。保存したJSONファイルを確認してください。iCloud Driveへ移動して保管することもできます。
8. 「バックアップから復元」でそのファイルを選びます。まずは **統合** を選んで件数を確認すると、同じ記録が二重にならないことを試せます。競合が表示された場合は中止してください。

Mac上のSafariの記録は、Lovableの公開サイト・他端末・Codex内のテストデータとは別です。本物の学習データの移行は、操作に慣れてから [移行手順](./local-migration.md) に沿って行ってください。現在の公開サイトにエクスポート機能がまだない場合は、公開サイトを変更せずに取り出す方法を別途確認してから進めます。

## 終了と次回の起動

- 終了：ターミナルで **Control + C** を押します。記録は通常のSafariのサイトデータに残ります。
- 次回：同じアプリフォルダをターミナルで開き、「5」の起動コマンドを実行してSafariで同じアドレスを開きます。
- `Port 5173 is already in use`：起動済みの別のターミナルがないか確認します。元のターミナルでControl + Cを押してから再実行してください。別のポートで起動すると別の保存領域になるため、むやみに変更しないでください。
- `Vite now supports tsconfig paths` などの案内が出ても、`ready` が表示されていれば利用できます。

通常のSafariウインドウを使ってください。プライベートブラウズ、サイトデータの削除、`localhost` と `127.0.0.1` の使い分けによって保存領域が変わったり消えたりします。いつも **http://127.0.0.1:5173/** を使い、JSONバックアップを残してください。アプリのフォルダをコピーするだけでは学習記録のバックアップにはなりません。
